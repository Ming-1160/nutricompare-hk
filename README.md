# NutriCompare HK

Traditional Chinese, mobile-responsive ITC2010 functional prototype for adults with type 2 diabetes and their caregivers in Hong Kong. Static HTML/CSS/JavaScript; no build dependencies, login, tracking, third-party runtime, stored health profile or paid API required. Project page (problem, plan, AI role, testing, limitations, ethics): [project.html](project.html).

## Version 1.10 · 12 November 2026

- **Loading that fails visibly and recovers.** Each data file is fetched on its own and in parallel. If a file does not arrive, the page says so above the results and offers 「再試一次」; a retry asks only for the missing files and keeps the person's conditions and compared foods. Before this version a failed price file was reported only inside a collapsed section, a missing Open Food Facts library also discarded the Hong Kong nutrition file, and there was no retry. A request is abandoned when no data has arrived for 10 seconds, so a stalled file no longer keeps the page waiting, while a large file on a slow connection can still finish. Allergens ticked while the data is still loading are kept and added to those in a link.
- **While data is missing, the page shows less instead of guessing.** Three rules, all in `app/data-loader.mjs` and none of them dependent on the data. (1) If one of the five label files is missing, no food is listed: some foods would otherwise show figures from a lower-ranked source that the reviewed label corrects (one soy sauce showed 7,592 mg sodium per 100 ml instead of 3,920 mg). (2) If any other file is missing and the person has chosen an allergen to avoid, no food is listed, because every file affects which allergen statement a food ends up with. (3) Comparing, the text for the AI and the suggested alternatives are paused whenever any file is missing. In each case the page says why and offers 「再試一次」. With only a nutrition reference or price file missing and no allergen chosen, foods are still listed under the notice; `app/tests/v110-data-loading.test.mjs` checks that those states show the complete catalogue's figures or "unknown", never a different figure. As a second check on the data, the same file goes through all 511 combinations of missing files: no food passes an allergen filter that it fails with every file loaded.
- **Brand words that are also everyday words.** An AI link or sentence such as `pure orange juice` used to return nothing because PURE is a brand in the catalogue. When no food matches the brand together with the food type, the words are read again without the brand list, and the page says the brand was not used and which search word was used instead (here 果汁, which lists every juice, as in v1.8). A brand that has matching foods is always kept, and budget or allergy conditions never cause a brand to be dropped.
- **Ranking by unit price.** 「單位價：低至高」 ranks by price per 100 g or 100 ml. Grams and millilitres are ranked as separate blocks and unknown unit prices come last. The ranking is applied after filtering, so `filterProducts` and the allergy exclusion are unchanged.
- **Comparison table.** Sodium now sits next to carbohydrates and sugars. Rows on one shared basis show the gap between the highest and lowest printed value. The gap and the 「最低」 mark appear only when every value in the row is known, and both are worked out from the figures exactly as printed. The row for the ranking in use is marked, including the whole-pack price row.
- **Privacy receipt and label lesson.** 「私隱收據」 lists the hosts the page contacted, the cookies a page script can read and browser storage, all read from the browser when opened. The page now sends no Referer, so the page address (which can hold the chosen allergens) is not attached to data requests or to links that open other websites. 「點樣睇營養標籤？」 is a one-minute lesson on an original sample label. Its statements are taken from three Centre for Food Safety documents and the GovHK nutrition labelling page, all linked in the lesson.
- **"Ask the AI to explain" (built, switched off).** 「叫 AI 解釋」 in the comparison writes a plain-text block of the figures on screen for the person to paste into the AI assistant; it contains food data only. The block names the rows the site itself does not rank (different units or pack sizes, different carbohydrate definitions, an unknown value) and tells the AI not to say which food is higher or lower for them. The button is hidden until `app/ai-config.mjs` has a working assistant link and `explainTested: true`, which the group should set only after tests 19 to 25 in [docs/maas-assistant.md](docs/maas-assistant.md) have passed. `tools/check-ai-numbers.mjs` lists any number in an AI reply that is not in the block. It cannot tell when a real number is attached to the wrong food, so a person still has to read the reply.
- **Start-up failures are visible.** `app/ai-config.mjs` is the file the group edits by hand. It is now read on its own, so a typing mistake there leaves the AI button hidden instead of stopping the site. If a program file is missing or damaged, the page says the program could not start and offers a reload instead of showing 「正在載入」 forever.
- **Smaller changes.** The sentence filter (rules on the device, not AI) and the AI assistant (EdUHK MaaS, another website) are named and ordered separately. After a sentence is applied, the conditions it set are repeated beside it with a 「睇結果」 button, because on a phone the results are below the fold. `linkExpires` in `app/ai-config.mjs` (YYYY-MM-DD) hides the AI button after that date and says the link has expired. The search box and shared links both allow 60 characters, and the page says so when a pasted sentence reaches that limit. On desktop the illustrative pack is a small icon so food names and figures reach the first screen. In product details the nutrition table comes before the label-checking record.
- **AI assistant connected (12 November, after the first v1.10 release).** The group's EdUHK MaaS agent is published and its login-free share link is in `app/ai-config.mjs` (it expires on 12 November 2027), so 「開啟 AI 助手」 now appears. The agent uses the platform's Deepseek-V4.1 model with the prompt in [docs/maas-assistant.md](docs/maas-assistant.md). Claude and Gemini models could not be used: the platform refuses Gemini with "not available in your region", and Claude-Opus-4.8 is priced at several hundred points per question against 1,000 points a month. On the published agent, the 21 condition tests (1–18 and 26–28) and the 7 "explain a comparison" tests (19–25) passed, and every link it wrote was accepted by the site's link checks with nothing ignored. The tests were run by an AI assistant through the share link without a login. They are not tests by group members or users. Settings, test results and the three prompt revisions are recorded in section 7 of the guide. 「叫 AI 解釋」 stays switched off (`explainTested: false`) until the group decides to turn it on. `tools/acceptance/v110.cjs` no longer assumes the settings file has no link: two checks follow the served settings, and a "no link yet" case was added.
- **Not in this version.** The English interface is not built. Real-user testing and the fieldwork label import are still pending. 「叫 AI 解釋」 is built and its tests passed, but it is switched off. Data files are unchanged, and the ten allergen exclusion sets still match v1.8.
- **Review.** This version was checked twice by AI reviewers (automated review, not user testing). A separate reviewer agent read the first build and reported 13 problems; the most serious was that an allergen ticked during loading could be removed by a link. Twelve are fixed. The thirteenth is a limit of the number-checking tool and is now stated in the tool and the guide. A three-seat council (three different Claude models, each reading the same brief on its own) then reviewed the result. One seat found that, with a label file missing, the comparison could mark the wrong food as 「最低」; rule (1) and rule (3) above come from that. The council also led to the 10-second limit, the start-up failure handling, the hidden AI button and the browser checks in `tools/acceptance/`. The changes made after the council were checked by their author only.
- **Verification (12 November, local server, Chromium).** `node --test app/tests/*.test.mjs` runs 220 tests: all pass with the original raw Pricewatch file available, and the portable copy passes 219 and skips the snapshot parity check. The browser checks in `tools/acceptance/` were run from a clean copy of the release files at phone (390 px emulation) and desktop (1366 px) sizes: 39 batch-1 checks and 109 v1.10 checks passed, including the load-failure, hold and start-up failure cases. axe-core 4.10 reported 0 WCAG 2.1 A/AA violations on 46 screens. After the assistant link was added the same day, everything was run again from a clean copy: the same 220 unit tests, 39 batch-1 checks and 111 v1.10 checks passed (two more than before, for the added "no link yet" case), with 0 axe violations on 47 screens. The check scripts were not run against the GitHub Pages address; after publishing, one page load there was looked at by hand (version label, the assistant button and one link written by the assistant). The browser checks never open the MaaS assistant; its own tests are in the guide. ## Version 1.7: 23 October 2026 (Moodle requirement gaps)

- **AI assistant hand-off.** An EdUHK MaaS Dialogue Agent (system prompt, settings and 15 test cases in [docs/maas-assistant.md](docs/maas-assistant.md)) turns one sentence into a condition card and a link. `app/url-state.mjs` validates every link value against fixed lists; unknown values are ignored and an unrecognised allergen produces a visible warning. Links can only add allergy exclusions. The assistant button appears after the published MaaS link is pasted into `app/ai-config.mjs`. AI suggests; the deterministic engine still decides allergy exclusion, arithmetic, ranking and prices.
- **Offline parser** (still not AI, runs only in the browser) was rewritten as a clause-by-clause reader and checked in six rounds of adversarial testing by a separate AI reviewer agent (automated checks, not user testing). Its safety rules, each covered by tests: allergy or refusal wording never becomes the product search; every allergen named in an allergy statement is kept, and anything it cannot name is reported ("unclear" words, allergies the label filter cannot cover such as molluscs or mustard, foods the site cannot exclude such as 朱古力); 有冇／沒有…嗎 questions ask for a product instead of hiding it; a negation word right before an allergen it could not read ("我唔會食花生", "not peanuts") makes it avoid that allergen and say it guessed. It also reads Cantonese and English refusals (唔食得, 食唔得, 唔想飲, 牛奶唔要, 除咗…都, I don't eat, keep away from, makes me sick), sugar/salt/carbohydrate wishes as rankings, budgets in digits, Chinese (百二蚊, 廿蚊) or English words (twenty dollars), and brand left-overs (嘉頓 30蚊以下). It is still a fixed-word helper: unusual sentences can be misread, so every condition appears as a removable chip and the allergy checkboxes stay authoritative.
- **Ranking:** 100ml and 100g values are ranked in separate blocks instead of not at all, so 低糖飲品 now lists 0g-sugar drinks first. New sort: 鈉：低至高.
- **Search precision:** "Cream crackers" / "ice cream" no longer match 夾心; the broad Consumer Council top-level groups are no longer searched (searching "soy" no longer returns every dairy product).
- **Usability:** shareable condition links and a link banner; empty results suggest single relaxations with counts (never allergy relaxation); comparison table marks the lowest value on a shared basis; compact coverage strip with the 1,000-label progress moved into a details panel; A+ large-text mode; a generated readability layer (`node tools/build-readability-css.mjs`) darkens 69 low-contrast text colours to at least 4.6:1 on the lightest panels and raises informative text below 12px.

- **Links** read the page's own allergen labels and everyday words (蛋類, 含麩質穀物, 牛奶製品, tree nuts, prawns), tell an unrecognised word (未能辨認) apart from an allergy the site cannot filter (網站篩唔到), warn that shellfish/seafood does not cover molluscs, and report repeated parameters; every `q` in an AI link is read for allergy wording.

## Features

- Chinese/English food and brand search across3,045 records:1,788 original HK price-comparison products plus1,257 separately labelled, unpriced OFF community nutrition references.24-item progressive loading; original priced catalogue shown by default. This release adds no new unpriced products; newly identified duplicate references are removed.

- AI assistant hand-off through validated links (EdUHK MaaS), plus a transparent fixed-keyword offline parser. Neither is a clinical recommendation engine.

## AI integration (v1.7)

The website contains no API keys. The AI part is an EdUHK MaaS Dialogue Agent published by the group as a share link (credits are charged to the developer account; the developer can see chat logs, so the site tells users not to enter personal or health details). The agent never sees product data: it only returns conditions and a link such as `?q=instant%20noodles&budget=20&sort=sodium-asc&avoid=peanuts&src=ai`. Accepted link keys: `q`, `cat` (biscuits, snacks, drinks, bakery, dairy, pantry, meals), `budget` (0–10000), `store` (merchant codes in the data), `avoid` (gluten, crustaceans, eggs, fish, peanuts, soy, milk, tree-nuts, sesame, sulphites, plus plain aliases), `sort` (relevance, price-asc, carbs-asc, sugar-asc, sodium-asc, protein-desc), `data`, `lib`, `src=ai`. The deterministic data/filter functions remain authoritative. Never ask patients to enter university credentials, and never put secrets into GitHub Pages.
